# SquirrelPad: goal loop for Conker's Bad Fur Day on iOS/iPadOS

**Status:** execution authorized 2026-09-26. Work the lowest unmet gate and record measured results in [STATUS.md](STATUS.md). The user supplied a private ROM after this loop was drafted. Native arm64 macOS control builds run; an iPad Simulator now shows Conker intro and game-select frames through RT64 Metal. The optional 52-buffer raytracing debug pipeline is gated off on unsupported Metal devices. Gameplay, input, audio, save and device gates remain open.

## Product goal and completion rule

Build a native Apple ARM64 iPhone/iPad app from [CBFD-Recompiled](https://github.com/sciaschi/CBFD-Recompiled), using a user-supplied, legally obtained **US big-endian `.z64` ROM**. The app must render the real game through Metal, play all game audio, accept touch and supported controllers, import the ROM through Files, preserve EEPROM saves and settings, survive normal mobile lifecycle events, and be reproducible as an audited, installable developer build. The game, rather than a launcher or a diagnostic scene, must be playable through the story on an iPad. iPhone must have a usable, tested layout and representative gameplay.

Complete means every gate below is supported by dated evidence from the exact build. Simulator evidence establishes builds, behavior and visible integration; sustained performance, touch feel, controller hardware, audio routes, interruptions and sleep require physical devices. If hardware or a valid private ROM is unavailable, label those gates **blocked by input**, never passed. Public distribution, TestFlight and App Store submission require a separate rights and release decision.

## Rules for every agentic cycle

1. **Observe:** read this document, the latest evidence entry, `git status`, source pins, disk availability, and the lowest open goal. Preserve unrelated dirty work and private data.
2. **Hypothesize:** name one failing gate, the expected result, and the narrowest source boundary to change. Keep Conker-specific changes separate from reusable RT64/runtime fixes.
3. **Act:** make the smallest reversible change. Pin exact dependency commits and record any patch against them. Do not run upstream `build.sh` against a dirty reference tree: it can reset/clean patched submodules. Use a dedicated working checkout or controlled patch application.
4. **Prove:** replay the failing check, then the adjacent regression check. Capture command, exit result, revision, device/runtime, log, and a visually inspected image/video for visual claims. A process, VI count, linked symbol, or title image is only its own gate.
5. **Record and repeat:** append a dated evidence entry with **Pass / Fail / Blocked by input / Not run**, the first reproducible failure, and the next exact command or action. Reopen any lower gate a later change breaks. Continue until the product goal is met or a named external input is required.

Use one Simulator at a time: boot, install, launch, capture, inspect, terminate and shut down the iPad before booting the iPhone (or vice versa). Do not erase an existing Simulator or app container without identifying and preserving data it may contain. For each port change, compare against the same macOS gameplay route where practical. Keep ordinary user flows as the acceptance path; private probes explain failures only.

## Execution decisions

1. **Delivery target:** this draft targets a locally signed developer build and full iPad story playability, with representative iPhone play. Public release is a separate decision.
2. **First iOS mod policy:** dynamic `.nrm` hooks stay disabled because upstream rewrites native code and invokes LiveRecomp; revisit only after the base game is accepted and an iOS-safe design exists.
3. **Private game input:** G0/G1 and game-backed Simulator gates require a valid US ROM supplied locally. The build must not fetch or publish one.
4. **Physical-device finish:** the loop can drive the installed Simulators on this machine autonomously. Completion still requires a real iPad and iPhone session; any unavailable device row remains open with an executable handoff.

The user authorized execution after supplying the ROM. Continue from the lowest unmet gate, keep the evidence ledger in `docs/STATUS.md`, and work until the completion rule is true. Device rows remain open until actual hardware is available.
